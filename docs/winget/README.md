# winget: как отправить VoxSpica

Манифест лежит по пути, под которому он и должен попасть в PR:

```
manifests/a/Alex37529/VoxSpica/0.1.5/VoxSpica.yaml
```

Он уже проверен по схеме самого winget
(`https://aka.ms/winget-manifest.singleton.1.30.0.schema.json`) — **0 ошибок**,
и SHA-256 совпадает с двумя независимыми источниками: `SHA256SUMS.txt` релиза
v0.1.5 и тем хешем, который GitHub сам считает для ассета.

## Почему переносимая сборка, а не установщик

В манифесте **один** установщик по умолчанию, а установщиков у нас семь — по
одному на язык. Никакого «выбери язык» в модели winget нет, поэтому
`InstallerType: zip` + `NestedInstallerType: portable` и переносимая сборка:
один zip, один exe, одинаковый для всех. Языковые установщики остаются на сайте
и на странице релиза — для winget они не годятся, для пользователя полезны.

**Да, файлы стоит выкладывать в Releases.** Именно это делает ссылку
канонической: ассет релиза неизменяемый, версионированный, отдаётся по прямой
ссылке и переживает любой следующий релиз. winget-ревьюеры это предпочитают
собственному хосту, и твоя текущая схема с ними совпадает.

## Как отправить

1. `gh repo fork microsoft/winget-pkgs --clone=false --remote=false`
2. Клонировать свой форк, создать ветку, скопировать из этого репозитория
   `docs/winget/manifests/a/Alex37529/` (в PR нужен путь `manifests/a/…`,
   без `docs/winget/`) и закоммитить.
3. Открыть PR в `microsoft/winget-pkgs`. Потребуется подписать CLA — бот
   Microsoft предложит, это один клик по ссылке в комментарии.
4. Дождаться проверок. Первая отправка от нового автора проходит ручное
   подтверждение мейнтейнерами: это нормально, занимает дни, а не часы.
5. После мержа: `winget source update`, затем `winget install Alex37529.VoxSpica`.

Либо одной командой, если есть токен GitHub с правом `repo` (классический
PAT, как в документации wingetcreate):

```powershell
wingetcreate submit --manifests .\docs\winget\manifests\a\Alex37529 -t <PAT>
```

## Что проверить в первом комментарии ревьюера

- **Подпись.** Не требуется для приёма, но некоторые ревьюеры спрашивают.
- **Теги.** Схема принимает любую строку (максимум 16), но список тегов в
  winget-pkgs контролируемый, и проверка может попросить заменить
  незнакомые. Из шести спорные — `Transcription` и `Dictation`; если скажут,
  оставлю `Speech`, `Microphone`, `Offline`, `Privacy`.
- **Версия схемы.** Стоит `1.30.0` — текущая. Пакет будет виден только
  клиентам winget новее 1.30; у тебя сейчас 1.29.380, так что первое время
  `winget install` может не найти пакет. Если нужна широкая доступность —
  скажи, поставлю `1.6.0` (все нужные поля там есть уже давно).
- **Описание.** На английском: у winget нет смысла в русском варианте, но
  `PackageLocale: en-US` можно продублировать вторым locale-манифестммм.

## Как обновлять

Манифест версии привязан к релизу. На 0.1.6 меняются `PackageVersion`,
`InstallerUrl`, `InstallerSha256` и `ReleaseDate`, а новая версия кладётся
рядом в `manifests/a/Alex37529/VoxSpica/0.1.6/`. Файл 0.1.5 не трогается —
в этом и смысл мультифайловой (по версиям) структуры: winget хранит историю
версий, и пользователь может откатиться.

Было бы правильно добавить это в релизный пайплайн (`wingetcreate update`),
но отдельная задача: сейчас обновление ручное.
